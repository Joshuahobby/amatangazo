# P1.1 — Contact-seller CTA (Claude Code task brief)

Paste this whole file to Claude Code as the task. It is self-contained: file paths, code, migration
commands, i18n keys, and acceptance criteria. Follow the steps in order.

---

## Goal

Every LIVE listing must give a non-owner one obvious primary way to reach the seller. Today:

- **JOB** — has `ApplyButton` ✅ (leave as is).
- **TENDER** — conversion is the submission flow (deadline + `documentUrl` + government source link) ✅ (leave as is).
- **AUCTION** — `AuctionDetails` already stores `registrationContactPhone / registrationContactWhatsapp / registrationContactEmail`, but they're buried in the spec `<dl>`. ❌ Promote to a prominent CTA.
- **CLASSIFIED** — has **no contact fields at all** (only `subcategory` + `price`). ❌ Add poster-provided contact fields and a CTA.

## Design decision (do not deviate)

Use **poster-provided contact fields**, never the private auth `User.phoneNumber`. Rationale:

- `User.phoneNumber` is an auth/identity field (optional, unique) — exposing it publicly is a privacy leak and it's often null for Google/email-OTP signups.
- Auctions already follow the poster-provided pattern; classifieds should mirror it for consistency.
- Because the poster explicitly chooses to publish these fields, the CTA can render **ungated** (no login required), matching how auction contact already renders.

Net: add `contactPhone` + `contactWhatsapp` to `ClassifiedDetails`, build one shared `ContactSeller`
component, and render it prominently for CLASSIFIED and AUCTION. Reuse it; don't fork per category.

model ClassifiedDetails {

## Step 4 — Shared `ContactSeller` component

Create `src/components/listing-details/contact-seller.tsx`. Server component (links only). Renders a
prominent card with Call / WhatsApp / Email actions; renders nothing if no contact is provided.

```tsx
import { getTranslations } from "next-intl/server";

/**
 * Prominent "how to reach the seller" CTA. Used by classified and auction detail
 * pages. Contact values are poster-provided (never the auth phone), so this
 * renders ungated. WhatsApp numbers are normalised to wa.me digit form.
 */
function toWhatsappDigits(raw: string): string {
  const digits = raw.replace(/\D/g, "");
  // Rwandan local "07…" → "2507…"; leave already-international numbers as-is.
  if (digits.startsWith("0")) return `250${digits.slice(1)}`;
  return digits;
}

export async function ContactSeller({
  title,
  phone,
  whatsapp,
  email,
  listingTitle,
}: {
  title: string;
  phone?: string | null;
  whatsapp?: string | null;
  email?: string | null;
  listingTitle: string;
}) {
  const t = await getTranslations("listing");
  if (!phone && !whatsapp && !email) return null;

  const waHref = whatsapp
    ? `https://wa.me/${toWhatsappDigits(whatsapp)}?text=${encodeURIComponent(t("contactMessage", { title: listingTitle }))}`
    : null;

  return (
    <section className="card my-4 border-primary/30 bg-primary/5">
      <p className="mb-3 font-semibold text-foreground">{title}</p>
      <div className="flex flex-wrap gap-2">
        {phone && (
          <a href={`tel:${phone}`} className="btn-primary">
            <svg className="h-4 w-4" fill="none" viewBox="0 0 24 24" stroke="currentColor" aria-hidden>
              <path strokeLinecap="round" strokeLinejoin="round" strokeWidth={2} d="M3 5a2 2 0 012-2h3.28a1 1 0 01.948.684l1.498 4.493a1 1 0 01-.502 1.21l-2.257 1.13a11.042 11.042 0 005.516 5.516l1.13-2.257a1 1 0 011.21-.502l4.493 1.498a1 1 0 01.684.949V19a2 2 0 01-2 2h-1C9.716 21 3 14.284 3 6V5z" />
            </svg>
            {t("callLabel")} {phone}
          </a>
        )}
        {waHref && (
          <a href={waHref} target="_blank" rel="noopener noreferrer" className="btn-outline">
            <svg className="h-4 w-4" fill="none" viewBox="0 0 24 24" stroke="currentColor" aria-hidden>
              <path strokeLinecap="round" strokeLinejoin="round" strokeWidth={2} d="M8.684 13.342C8.886 12.938 9 12.482 9 12c0-.482-.114-.938-.316-1.342m0 2.684a3 3 0 110-2.684m0 2.684l6.632 3.316m-6.632-6l6.632-3.316m0 0a3 3 0 105.367-2.684 3 3 0 00-5.367 2.684zm0 9.316a3 3 0 105.368 2.684 3 3 0 00-5.368-2.684z" />
            </svg>
            {t("whatsapp")}
          </a>
        )}
        {email && (
          <a href={`mailto:${email}`} className="btn-outline">
            {t("email")}
          </a>
        )}
      </div>
    </section>
  );
}
```

## Out of scope

- No live-bidding or in-app messaging — just direct contact links.
- No change to JOB (Apply) or TENDER (submission) flows.
- Don't touch the private `User.phoneNumber`.

## Acceptance criteria

1. As a logged-out or non-owner user on a **LIVE classified** that has contact info, a prominent
   "Contact seller" card shows Call and/or WhatsApp actions above the description.
2. On a **LIVE auction**, the same card shows "Register for this auction" with the registration
   phone/WhatsApp/email, and those rows no longer appear in the spec grid below.
3. WhatsApp links open a chat to the normalised number with the listing title prefilled.
4. Owners viewing their own listing do **not** see the contact CTA (they see Boost, as before).
5. Classifieds with no contact info render no empty card (component returns null).
6. The classified post form accepts and persists the two new optional fields.
7. All three locales render with no missing-key errors.
